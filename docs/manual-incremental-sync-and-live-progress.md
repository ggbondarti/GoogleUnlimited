# GoogleUnlimited 实时上传监控与手动增量同步

## 目标

本次改造只处理本地队列可观测性与本地文件增量发现，不实现 Google Photos 双向删除同步，不调用云端删除接口，也不删除任何本地文件。

## 1. 实时上传监控

- gotohp CLI 增加 `--json-progress`，通过 stderr 输出 JSON Lines 事件，stdout 保持原有最终 JSON 结果。
- 进度事件只包含事件类型、文件名（basename）、处理阶段、已发送字节、总字节、重试次数和时间；不输出绝对路径、Cookie、Token、MediaKey 或原始错误响应。
- BytesUploaded 是 gotohp 实际读取并发送到上传请求体的字节，不冒充 Google API 已确认接收的字节；WebUI 据此计算当前文件百分比、速度、耗时与文件 ETA。
- 成功任务记录完成时间和耗时；最近 20 个有耗时样本用于平均单文件耗时，至少有 3 个成功样本才显示队列 ETA。样本不足或速度为零时明确说明原因。
- 页面每秒读取轻量 /api/progress；每 4 秒读取普通状态。两者只读内存/SQLite，不扫描磁盘。
- 默认只展示当前/最近完成文件摘要；详细速度、字节进度、平均耗时和队列 ETA 放在折叠详情内。

## 2. 手动增量扫描

- 取消 worker 每 30 秒的全目录扫描。
- 首次添加来源、同一路径重新挂载、恢复归档来源时各扫描一次。
- 用户可以对单个来源点击“增量扫描”；顶部“扫描所有来源”仍为显式手动操作。
- 开启/关闭全局同步、来源上传许可、暂停/恢复来源都不触发磁盘扫描。
- 扫描只读本地目录并更新 SQLite；扫描本身绝不授权上传。

## 3. 扫描预览与上传确认

- 新文件和内容发生变化的文件进入“待确认”，不进入可上传队列。
- 内容未变化的历史记录保留原状态；相同内容已被 API 接收的文件标记为去重，不重复上传。
- 内容变化时先将旧版本快照写入历史表，再将当前版本标记为待确认；不覆盖/删除云端旧照片。
- 扫描预览列出新增、变化、重复、已存在、不稳定、不可用来源、本地缺失统计及待确认文件大小；单来源扫描展示该来源的统计，扫描所有来源则不把汇总数字错误分摊到每个来源。
- 用户可取消勾选不需要的候选；未勾选项继续留在待确认列表。
- 用户确认后，仅选中的候选从待确认转为 queued。仍需满足原有全局上传开关、来源上传许可、相册确认、账号授权和画质配置。
- 首次添加/重新挂载只做扫描，不会因为全局同步开关已经开启就自动上传新候选。
- 单张试传仍是独立的显式操作，可从待确认图片中选择一张。

## 4. 数据与安全边界

- SQLite 通过向后兼容的 ALTER TABLE 迁移增加必要字段/历史表，不删除旧记录。
- API 已接收与 Google Photos 页面人工核验继续分开统计。
- 隐藏来源不等于删除来源；重新添加同一路径复用原 source ID、相册设置与上传历史。重新挂载会将此前暂停的已确认任务恢复为 queued，但同时将来源上传许可重置为 OFF，因此不会自动上传。
- 不实现云端删除同步；云端移除/删除都不会触发本地删除。
- 本次开发不自动重启正在运行的 WebUI、不打断上传、不推送 GitHub。部署/推送需另行明确授权。

## 5. 验收

1. 新来源扫描后只出现待确认候选，worker 无法选中它们。
2. 只确认部分候选时，仅所选文件进入队列。
3. 同一路径重新挂载只登记新增/变化项，已接受文件保持原状态。
4. 修改已上传文件会保留旧版本记录，并要求确认新版本。
5. worker 不再定时扫描；全局/来源开关不触发扫描。
6. gotohp 真实进度事件可传到 WebUI；测试覆盖 JSONL、脱敏、速度/ETA 计算与 SQLite 迁移。
7. 原有 WebUI、CLI、去重、单张试传、相册绑定和授权回归通过。

## 6. 本机实现与验收记录（2026-11-16）

- gotohp ARM64 本地构建已重新编译，并通过构建清单校验；`--json-progress` 通过 stderr 输出 JSONL，原有 stdout 最终结果保持不变。
- WebUI 读取进度时不扫描磁盘；JSONL 读取器会去除记录末尾的 CR/LF，再交给进度解析器。
- 完整 Python 回归 **57/57 通过**；Go `go test ./...` 通过。
- `/api/status` 与 `/api/progress` 返回 HTTP 200。单张真实试传成功，结果为 `api_accepted`，复用了已绑定的相册；全局批量开关在单张测试期间保持关闭。
- 随后恢复全局同步，队列开始连续处理；API 接收状态仍不等同于 Google Photos 页面人工核验。
